Deploying an automated risk governor requires strict operational security. A bot is a software application interacting with financial infrastructure via network sockets. If your host machine loses power, your internet drops packets, or your API credentials are inappropriately scoped, your account faces catastrophic risk independent of market conditions.

### 1. Generating scoped API tokens

On the Deriv developer portal, API tokens can be created with specific privilege scopes: `read`, `trade`, `payments`, `admin`, and `trading_information`.

**The security rule is absolute:**
- **Required scopes**: Enable `read` and `trade` ONLY.
- **Forbidden scopes**: NEVER check `payments` or `admin`. 

An API token with `read` and `trade` can inspect balance and buy contracts. It has zero capability to withdraw funds, modify account passwords, or transfer balances to external wallets. Even if your VPS environment were compromised, your deposited funds cannot be stolen by an attacker.

### 2. Deploying on a reliable Linux VPS

Running trading bots from a local laptop or smartphone in Nigeria exposes execution to two critical hazards:
- Public grid power outages that terminate processes mid-sequence.
- Mobile cellular network latency spikes that cause socket disconnects and duplicate order packets.

Deploy The Enforcer on an inexpensive Linux VPS (e.g., DigitalOcean, Hetzner, or AWS Lightsail, typically $4 to $6 per month) situated in close geographic proximity to Deriv's primary WebSocket servers (London or Frankfurt).

The standard deployment sequence uses Docker:

```bash
# 1. Clone the repository
git clone https://github.com/harrisonojek/softpip-enforcer.git
cd softpip-enforcer

# 2. Configure credentials
cp config.example.yaml config.yaml
# Edit config.yaml: insert read/trade token and Telegram bot ID

# 3. Launch isolated container
docker compose up -d
```

### 3. Implementing the socket kill switch

The Enforcer incorporates an automated heartbeat check (`ping`/`pong` every 15 seconds) over the WebSocket connection.

If the socket fails to receive a server `pong` within 30 seconds:
1. The process immediately pauses order dispatch.
2. It logs an alert to your configured Telegram channel.
3. Upon reconnection, it queries `proposal_open_contract` to inspect the exact state of any pending contracts before resetting local trade memory.
4. If an unhandled API error (such as `InsufficientBalance` or `TokenExpired`) occurs, the script executes a hard exit (`sys.exit(1)`), refusing to enter reconnect retry loops that could double-order capital.
